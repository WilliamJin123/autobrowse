## 2. Do not copy

- **Chinese-only skill and references** (`smart-search/SKILL.md:3-8`, `api-discovery.md:27`): the agent cannot skim them cheaply, and a `docs/zh` mirror drifts.
- **Mandatory full-catalog dump** (`smart-search/SKILL.md:14`): it spends tokens and contradicts their own `opencli-usage/SKILL.md:20`.
- **Hand-written `llms.txt` and `PRIVACY.md` permission table**: both are already stale. Generate them.
- **`postinstall` that fetches adapters over the network** (`package.json:57`): bad supply-chain surface for a tool that holds credentials.
- **Committed 1 MB `cli-manifest.json` with a drift gate** (`release.yml`): we have no per-site adapter catalog to justify it.
- **`opencli-*` prefix filter** (`src/skills.ts:38`, `package.json:33`): it silently drops `smart-search` from the package, yet the README tells people to install it.
- **`docs/superpowers/plans` internal planning docs inside the public docs tree**: noise for readers.

## 3. Top three upgrades

1. JSON by default, with an `{ok,data|error}` envelope and typed exit codes, in `src/app/output.ts` and the catch at `cli.ts:995`. Today every caller parses prose and cannot tell auth-refused from a gate refusal.
2. Ship the generic skill and a generated `llms.txt` inside the npm package, with `autobrowse skills list|read|install`. Today a `npm i` user gets no agent guidance.
3. One paged `autobrowse list [query]` plus `--help --json` with `next:` hints. This replaces four finder commands and gives agents a machine-readable catalogue.
