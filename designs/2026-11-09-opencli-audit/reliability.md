2. Do not copy
- **Regex-only redaction (`observation/redaction.ts:14-49`):** AB's held-secret masking with a re-scan is stronger.
- **Message-pattern retry fallback (`browser/errors.ts:84-112`):** fragile. Only copy the code table.
- **Semantic retry with a new id (`daemon-client.ts:~478`):** safe for OpenCLI's pre-dispatch faults only. AB writes run once under Restate.
- **TTL lease reclaim (`session-lease.ts:26`):** AB's durable profile wait and Restate journal already cover this.
- **Slot pool of warm tabs (`site-slots.ts`):** AB's model is one profile per account.
- **Extension/daemon doctor checks (`doctor.ts:105-235`):** AB has no extension. Only the flaky re-check pattern transfers.
- **Table/CSV/YAML formats (`output.ts:43-146`):** low value for an agent-driven CLI.
- **Navigation-based `auth refresh` touch (`auth.ts:236-263`):** risky on flag-prone sites such as LinkedIn. Pace it through caps if built.
- **120s ring buffer with full network bodies (`observation/session.ts:5`):** large and a secret risk. Keep AB's redacted network artifact.

3. Top upgrades, in order
1. A single `{ok,data|error{code,message,hint,exitCode,outcome,artifacts}}` CLI envelope with an exit-code table, built from `ACCESS_CODES`, `SendVerdict` and `errorBody`.
2. An artifact pointer on `FlowRunRow`, `SiteCallRow` and the error, plus `--trace on` and count/byte retention caps, so repair starts from a link.
3. `autobrowse auth status`, a no-sign-in per-profile logged_in/unknown/not check with recovery commands, and a doctor that reports `issues[]`, re-checks for flakiness and exits nonzero.
