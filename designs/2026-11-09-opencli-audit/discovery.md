## 2. Do not copy

- **Patched `fetch` and XHR with a disguised `toString`** (`src/interceptor.ts:26-118`). It is detectable, it breaks on service workers, and autobrowse's passive response listener already covers it.
- **Global-store `tap` into Pinia and Vuex** (`tap.ts:61-115`). It calls site code in a signed-in session, which is a send gate and ban risk for our accounts.
- **yt-dlp with `--cookies-from-browser`** (`download/index.ts:307-317`). It copies session cookies out of the profile; autobrowse rejected cookie export (`designs/2026-10-28-signed-in-reads.md`, option C).
- **Fetching a Twitter queryId from a GitHub raw file at run time** (`twitter/shared.js:283-330`). Our rule is that no signed-in page contacts a third party.
- **Hardcoded per-site field dictionaries as code** (`field-conventions.md`). Keep them as redacted site memory, not source.
- **Batch parallel fetch** (`fetch.ts:89-125`). It breaks per-site pace and caps.
- **The 24h on-disk cache of full bodies** (`network-cache.ts`). It stores private data. Keep shapes plus a keyed pointer only.
- **`--static` against third-party script URLs from Node** (`discover.ts:162`). Our flows must not make cookieless fetches that reveal the profile's IP.

## 3. Top three upgrades

1. **An `api` op in the compiler and `code` runtime** (`src/compiler/outline.ts`, `src/browser/code.ts`), backed by a shared in-page `pageJson` helper with login-wall check, named headers, cursor loop and repeated-cursor error. It turns a found JSON call into a durable, model-free read, and replaces the five hand-rolled `fetch`es.
2. **`discover.ts` in explore.** It adds shape-with-types rows keyed by operation name, a field filter, and a static AST scan merged with the capture (`network.ts`, `explore/commands.ts`, `server.ts:904`), with capture default-on in explore. It makes finding the JSON behind a page a command, not a manual hunt.
3. **A per-site redacted `endpoints.json` and `field-map.json`**, written from kept sessions and read by the explorer and by `heal`. Endpoint knowledge then survives across sessions and across the model.

I did not find `api_candidates` or `real_data_score` anywhere in OpenCLI `src/`. They appear only in the docs (`api-discovery.md:74-81`), so I treat them as unimplemented.
